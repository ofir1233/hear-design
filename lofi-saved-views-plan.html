A. Yes, treat as "working state" overlay on the view

Part 3 of 3
Edge cases
Tagged Handle v1 for must-design-now, Punt v2 for things to acknowledge but defer.
01Handle v1
Loading a view whose columns no longer exist
Signal was renamed/removed. Show a soft toast: "2 columns from this view are no longer available." Drop silently from selection. Don't block load.
02Handle v1
Loading a view with filters on missing fields
Same pattern as #01 — toast + drop. Filters and columns share the same "field went away" mechanic.
03Handle v1
Dirty state — switching views with unsaved changes
Confirm dialog: "You have unsaved changes to Compliance — Q2. Discard / Save as new / Cancel."
04Handle v1
Empty state — no views saved yet
Dropdown shows "No saved views yet" + a prominent "Save current as new view" action. View selector shows "Untitled view" with a save nudge.
05Handle v1
Migration of existing presets
Existing presets become views with the project's current default column set. Surface a one-time tooltip on first visit so users know.
06Handle v1
Default view per project
One default per user per project. "Set as default" in dropdown. On project load, default applies automatically.
07Punt v2
Conflicting edits on a shared org view
v1: last-write-wins, no locking. Document the limitation. Address later if it becomes a real problem.
08Punt v2
Shareable URL for a view
v1: rely on view ID being persistent. Deep-link URLs that encode the full state come later.
09Handle v1
Narrow viewport / zoom behavior
Strip already has horizontal scroll for filter rows. Columns section's two-pane layout collapses to a single pane below ~900px (tabs: Available / Order).
10Punt v2
Performance — debouncing column toggles
Apply is explicit (button), so toggles don't re-query. Only matters when row count scales up — design is safe, eng concern later.
11Handle v1
Reset to defaults — what does it reset?
See decision #7. Resets to currently loaded view's saved state. Secondary "Clear view → system default" link if user wants a true wipe.
12Punt v2
View rename collisions
v1: allow duplicate names, disambiguate by scope (Project/Org). v2: warn on collision.
